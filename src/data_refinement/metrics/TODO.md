# TODO (metrics)

Deferred cross-cutting considerations for this directory, raised while building the seventeenlands containers (sts_gg, draft_data, game_data, and eventually replay_data). Intentionally not acted on yet — revisit once all three seventeenlands sources have a first round of metrics implemented, so any refactor is informed by all three shapes rather than guessed at from just one or two.

- **Standardize metric constructor argument shape across containers.** `sts_gg`'s `CardAverageMetric`/`DeckLabelMetric` always thread `card_binder`/`deck_box` for cross-class signature consistency within that container, even when a given subclass never uses one. `draft_data`/`game_data` instead followed a leaner rule: a metric that has no use for `deck_box` simply omits the parameter. Decide whether one convention should win project-wide, or whether the divergence is fine because each container is internally consistent.
- **Deduplicate the repeated running-tally Template Method shape.** `sts_gg/card_average_metric.py`'s `CardAverageMetric`, `draft_data/pack_card_tally_metric.py`'s `PackCardTallyMetric`, and `game_data/game_card_average_metric.py`'s `GameCardAverageMetric` are now three independent implementations of essentially the same per-key running `(value_sum/times_in_pack, total_count/times_picked)` accumulate-then-average shape. Each was kept separate deliberately (per-container constructor conventions, differing key shapes) rather than forcing a shared abstraction prematurely - but three near-identical implementations is a real duplication signal worth a dedicated look once replay_data's own metrics (which may add a fourth) are in.
- **Deduplicate the card-name-matching policy.** `DraftCardColumns._match_uuid()` (draft_data) and `GameCardColumns._match_uuid()` (game_data) both re-implement the exact same 17lands-wide policy (exact name match, else split/MDFC front-face regex fallback, else unmatched) byte-for-byte, on the grounds that duplicating a small, stable policy per per-source columns-index class is cheaper than a shared abstraction. Once replay_data's own columns-index class likely adds a third copy, revisit whether a small shared helper (a function, not a class/wrapper) is warranted - being careful not to reintroduce the `name_lookup.py`/`CardNameLedger` wrapper-class shape that was explicitly rejected earlier.
